===============================================================
3. INSTALL IN FIVE MINUTES (APACHE)
===============================================================

1. Copy the folder "digital-leap" into the XAMPP web root, for example:
      C:\xampp\htdocs\digital-leap

2. Start Apache and MySQL from the XAMPP Control Panel.

3. Create the database. Either:

   a) Open http://localhost/phpmyadmin, click Import, choose
      database/digital_leap.sql and press Go.

   b) Or use a command prompt:
      C:\xampp\mysql\bin\mysql.exe -u root < "C:\path\to\database\digital_leap.sql"

   The script creates the database "digital_leap", all 33 tables,
   constraints, indexes and the seed data. It DROPS and recreates every
   application table, so it is only safe on a disposable clean
   installation: never run it over a database that holds real student
   work, and never use it to upgrade a live system.

4. Create the configuration file:
      copy config\config.sample.php config\config.php

   The defaults match a standard XAMPP installation
   (host 127.0.0.1, port 3306, user root, empty password).
   Edit only if your MySQL credentials differ.

5. Open:
      http://localhost/digital-leap/

   The login page should appear.

===============================================================
4. ALTERNATIVE: PHP BUILT-IN SERVER
===============================================================

From the digital-leap folder:

   C:\xampp\php\php.exe -S 127.0.0.1:8080 router.php

Then open http://127.0.0.1:8080/

router.php blocks direct access to /app, /bin, /config, /storage and
/database, so the application behaves like the Apache deployment.

6. FIRST STEPS
===============================================================

- Sign in as the coordinator to see the operational dashboard.
- Sign in as the supervisor to review submitted logbook weeks.
- Sign in as the mentor to review entries and assess the report.
- Sign in as the student to see the published result and open the
  official 16-page log book template from the Logbook page. The
  Career Fair 2026 page opens the participation report template and
  accepts the completed report for the assessment portfolio.
- Sign in as the administrator to inspect users, settings and the
  audit trail. The programme list on the account form is grouped by
  the five Limkokwing faculties.

Every signed-in role also sees "Ask DIVA" in the navigation. DIVA
answers from the placement records the account may read and from an
offline text extract of the internship guidebook, citing page numbers.
Open Ask DIVA and try "How is my progress calculated?", then use
"Check my report draft" with a .docx or pasted text. DIVA saves questions
and answers to your account but never modifies internship records or gives
a mark. Use New conversation for a separate topic and the history sidebar
to reopen or find an earlier conversation. Archive hides a conversation;
it does not delete stored data. Saved answers reflect the time they were
asked. For live information, ask again.

Students, mentors and coordinators see "Messages". Sign in as the
student: the start list offers only the assigned mentor and the
coordinator. A reply quotes the parent message, an unread count shows
in the navigation, and polling refreshes the thread every eight
seconds. Host supervisors use the logbook entry discussion instead.

The log book template is also linked from the supervisor queue, the
mentor logbook and the coordinator placements page, so every role
that handles logbooks can open or download it. Uploaded Career Fair
reports appear for the mentor under Reports and for the coordinator
in the placement's Documents list.

Students check in and out at the placement from the Attendance card on
My placement. The browser asks for location only when Check in or Check
out is pressed; the time and, once a coordinator has set the site pin on
the organisation form, the distance from that pin are stored. Declining
the prompt still records an attested check-in, so nothing depends on the
permission being granted. The shipped Permissions-Policy header allows
geolocation for this site only (geolocation=(self)); no map, geocoder or
other internet service is contacted. Staff visits use the same reading:
a mentor presses Check in at site on the visit row before completing a
physical visit, and a coordinator records a monitoring check-in on the
placement page. Both are refused if the reading is more than 500 m from
the site pin, and both are stored with the name, role, time and distance;
virtual and phone visits need no check-in. A finished day in the log book can
also be sent to the host supervisor and academic mentor straight away
with Send on its row; the full week still goes to both on submit.

Every signed-in role has "My settings" in the account menu and at the
foot of the sidebar. Four boxes choose which notifications are also
copied to email — the bell always keeps every item — and text size and
reduced motion preview as soon as they are picked. The choices are
stored per account in user_preference and follow the person to any
other device. The same page shows what the current browser is holding
for offline work, offers the install again if it was declined during
the first visit, and can clear this device's saved DIVA answers and
browsed pages without touching any record in the database.

Every signed-in role also has "Guidebook" in the navigation. It opens
the published 25-page guidebook PDF in the browser, keeps the same file
as a download with its size on the button, and lists all 25 pages so any
one can be opened in the PDF viewer at that page. DIVA's citation pages
remain plain text and each links back to the PDF. Downloading writes a
guidebook.download audit event; merely opening it does not.

The complete role-by-role script, with expected results, is in
docs/VERIFY.md.

7. MAINTENANCE COMMANDS
===============================================================

From the digital-leap folder:

  C:\xampp\php\php.exe bin\send_daily_records.php
      Emails each newly saved logbook day to the placement's host
      supervisor and academic mentor. Run it once a day before the
      mail queue. Only days on a week that is still a draft are sent;
      a submitted week travels once, as a full weekly email. Use
      --dry-run to preview, or --date=YYYY-MM-DD to run as at
      another date. A student can also press Send on a finished day
      row in the log book to queue that day immediately; the same
      record is never sent twice.

  C:\xampp\php\php.exe bin\send_mail_queue.php
      Processes due messages in email_queue. In the default log
      mode, messages are appended to storage\logs\mail.log.

  C:\xampp\php\php.exe bin\remind_logbooks.php
      Creates weekly reminders for placements with overdue logbooks.

  C:\xampp\php\php.exe bin\diva-eval.php
      Runs the expanded DIVA evaluation set and prints the intent,
      the answering tier, the cited pages and the tier totals. Add
      --answers to print each answer, or --user=<id> to fix the
      signed-in account. It changes no data.

  C:\xampp\php\php.exe bin\build-diva-corpus.php "guidebook.pdf"
      Regenerates storage\knowledge\guidebook.txt from the PDF. Only
      needed if the guidebook is replaced; requires pdftotext on the
      development machine. The shipped application never parses the
      PDF at runtime.

The three scheduled jobs can be run with Windows Task Scheduler. The
administrator can also process the queue from the mail screen.

the seed links to ship in digital-leap/storage/uploads, and the log

===============================================================
9. TROUBLESHOOTING
===============================================================

"Database connection failed"
  MySQL is not running, or config/config.php has the wrong
  credentials. Start MySQL and check host, port, user and password.

404 on every page under Apache
  mod_rewrite is disabled, or the folder is not under htdocs.
  Enable mod_rewrite in httpd.conf and confirm the URL.

Styles or scripts do not load
  The application must be opened through the site root
  (http://localhost/digital-leap/), not by double-clicking index.php.

"419" when submitting a form
  The session expired or the page was left open too long. Reload the
  form and submit again; CSRF tokens rotate with the session.

Account temporarily locked
  Five failed sign-ins lock an account for 15 minutes. The
  administrator can unlock it from Users.

10. SECURITY NOTES FOR THE MARKER
===============================================================

- config/config.php is excluded from the zip and must be created
  locally. No real credentials are shipped.
- Uploaded files live in storage/uploads inside the application folder but
  are not reachable over HTTP: storage/.htaccess returns 403 to any direct
  request under Apache, router.php returns 404 for the same paths on the
  built-in server, and the files themselves are served only through
  DownloadController after an ownership check. This is an access-control
  boundary, not a physical move outside the web root.
- The default mail mode is "log"; no email leaves the machine.
- The sign-in and registration forms enforce one password policy: at
  least eight characters with an uppercase letter, a lowercase letter
  and a number. Symbols are optional and shown in a strength meter.
- Dynamic pages are sent with Cache-Control: no-store and logout sends
  Clear-Site-Data, so the browser Back button cannot reopen a signed-out
  dashboard.
- The internship log book template is served only to signed-in users
  through DownloadController; it can be viewed inline or downloaded.
  The Career Fair 2026 template is served the same way from
  storage/templates/career_fair_2026_report_template.pdf, and the
  guidebook from storage/templates/Internship_Guidebook_LEAP_Clean_Layout.pdf.
  A download, not an inline view, writes the template's audit event.
- Profile photos are limited to JPG, PNG or WebP at 8 MB, kept in
  storage/uploads/avatars under the same deny-all rule as the other
  uploads, and served only through ?r=avatar, which checks that the viewer
  may already see that person. The CSP
  allows blob: only so the chosen photo can be previewed locally before
  it is saved; no external image source is permitted.
- DIVA cannot approve work, publish grades or send messages, and answers
  from records the signed-in account may read. Chat history stores the
  question, answer, source references and answer basis in the local DB.
  Other application accounts cannot open it, but DB administrators can;
  do not enter passwords or other secrets. Archive retains the rows.
  Network calls occur only if the optional loopback local model is enabled.
  Audit metadata holds intent, tier, cited pages and a question hash,
  not raw question/report text.
- Messages are scoped by the placement: a student can message only the
  assigned mentor, the host supervisor or the coordinator, never another
  student. Edits are limited to the sender's own text messages inside 15
  minutes, deletion leaves a tombstone, and a repeated POST with the same
  client token stores one message. All message tables use utf8mb4 so
  emoji survive.
- Demo passwords are for assessment only and must be changed before
  any real use.

11. HTTPS, THE INSTALLABLE APP AND OTHER HOSTS
===============================================================

The browser registers a service worker, and therefore offers "Install
app" and serves cached pages offline, only on https:// or
http://localhost. On plain HTTP over a network address every page
still works; only the installable, offline part is unavailable.

Declining the install banner hides the banner, not the option: "How to
install this app" stays in the account menu and on My settings, and the
browser's own address-bar install icon is unaffected. Desktop Firefox
does not offer a user-controlled install button for this kind of app,
so on that browser the note explains it and points to Chrome or Edge
instead of showing a control that does nothing.

- Terminate TLS at Apache, or at a reverse proxy in front of it, and
  open the site over https. The application adds HSTS and the Secure
  cookie flag whenever PHP sees an HTTPS request.
- A self-signed certificate is rejected for service-worker
  registration by current browsers; use a trusted certificate or test
  on localhost.
- After deploying a change to cached files, bump the version string in
  sw.js so the browser replaces the old shell.

Full deployment notes are in deploy/README.md. In short:

- Apache: the document root is digital-leap/. The .htaccess files
  rewrite routes and deny app/, bin/, config/ and storage/;
  deploy/apache-vhost.conf repeats that for a self-managed server.
- Docker: copy the sample config, set db.host to "db" and db.pass to
  the compose password, then run
  docker compose -f deploy/docker-compose.yml up --build
  and open http://localhost:8080/. The image has not been built on
  the packaging machine (no Docker engine); treat the first build as
  unverified.
- GitHub Codespaces: open
  https://codespaces.new/EssenceShady/Digital_LEAP_Assignment3_Group_G
  and create the codespace. .devcontainer/ builds the image, starts
  MariaDB, imports the seed and publishes the app on port 8080 with a
  public forwarded link. Use that link to share the running app; start
  the codespace again if it has stopped on idle. Nothing reaches the
  internet from the application itself.
- GitHub checkout: config/config.php is git-ignored, so create it from
  the sample after cloning. .github/workflows/lint.yml runs php -l
  and node --check on every push and needs no secrets.
- Upgrading a live database: apply database/migrations/*.sql in date
  order. Never re-import digital_leap.sql over existing work.
